# GIF 工坊 · 公众号专用

把录屏生成的 GIF 一键处理成公众号能直接粘贴的格式：**体积 < 10MB、帧数 ≤ 300**。
全程在本机完成，文件不外传。

## 快速开始

**双击 `启动 GIF 工坊.command`**，浏览器会自动打开 http://127.0.0.1:8600 ，关闭终端窗口即退出。

- 首次运行会自动创建独立虚拟环境（`.venv`）并安装依赖，需联网，约 1 分钟；之后秒开。
- macOS 第一次打开可能提示"无法验证开发者"：在文件上 **右键 → 打开 → 打开** 一次即可，之后双击就行。
- 如果已经开着一个，再双击只会重新打开浏览器页面。

```bash
# 也可以在终端里用
git clone https://github.com/xiaohuailabs/gif-for-wechat.git
cd gif-for-wechat
pip install -r requirements.txt

# 方式一: Web 界面(推荐)
python3 app.py                # 自动打开 http://127.0.0.1:8600
python3 app.py --port 9000    # 换端口

# 方式二: 命令行处理单个文件
python3 app.py input.gif                      # 智能压缩
python3 app.py input.gif -o out.gif           # 指定输出
python3 app.py input.gif --frame-drop 1in2 --scale 0.8 --colors 128   # 手动参数
```

依赖：Python 3.9+，`pip install -r requirements.txt`（flask、pillow）。
压缩引擎：优先用 **ffmpeg**（`brew install ffmpeg`，画质与体积最均衡）；没有 ffmpeg 时自动降级 Pillow 兜底（透明背景会变白底）。

## 两种模式

**智能模式**——不用管参数：先做不损画质的纯优化（全局调色板 + 差异区域编码），不达标再沿策略阶梯逐级加压（缩放 → 减色 → 抽帧），命中即停，永远用最温和的达标方案。可选三档策略：均衡 / 画质优先 / 极限压缩。

**手动模式**——每个选项自己选，优缺点一目了然：

| 选项 | 档位 | 说明 |
|------|------|------|
| 抽帧 | 不丢 / 每隔9、4、3、2、1帧丢1帧 | 直接减帧数与体积；丢得越多动画越卡 |
| 缩放 | 100% ~ 40% | 对体积影响最大；小字内容不建议低于 80% |
| 色彩数 | 256 ~ 32 色 | UI 录屏降到 128 色几乎无感知 |
| 抖动 | 无 / 轻微 / 明显 / 强烈 | 用有限颜色模拟更多色彩，越强文件越大 |

每个档位都标注了「影响」和 ✓优点 / ✗缺点，选之前就能看到后果。另有一键组合（只抽帧 / 只缩放 / 只减色 / 温和三件套 / 强力三件套）快速铺满四项。

帧数是硬约束：任何模式下超过 300 帧都会自动补抽帧，并在结果里明确告知。

## 使用流程

1. 拖入 GIF（或点击选择，支持多选）——**只是装片，不会自动处理**
2. 装片后每张卡片会显示原图缩略图、体积 / 帧数 / 尺寸，超限的数值标橙色，并提示"将使用什么方案"
3. 在下方控制台选好模式（智能 / 手动）和参数，需要的话调整目标体积、帧数上限、宽度上限
4. 点卡片上的 **开始处理**（多个文件可点「全部开始」），进度以「逐帧过片」动画实时显示
5. 结果页看前后对比（体积 / 帧数 / 尺寸 / 帧率）、使用的压缩手段、警告
6. 点「复制到剪贴板」→ 在公众号编辑器里 Ctrl+V 粘贴
   （浏览器不支持复制图片时会自动打开图片，可右键复制或直接拖进编辑器）
7. 不满意可以改设置点「重新处理」，同一个文件换参数即时对比

页面从上到下依次是：**01 装片 → 02 出片区 → 03 控制台**。结果在上、设置在下。

## 全局设置

- **目标体积**：默认 9.5MB（留 0.5MB 余量防平台计量误差）
- **帧数上限**：默认 300
- **宽度上限**：公众号正文宽约 678–900px，高清录屏（如 1920px 宽）建议设为 900，体积会明显下降

## 设计说明

界面不是通用后台模板，而是一台「帧处理仪器」的概念设计：

- **概念**：FRAME LAB 冲印工作台——暖白相纸底 + 坐标纸网格 + 顶部绿色光晕；黑色仪器铭牌（logo 与 FFMPEG READY 状态灯）贴在纸面上，形成强对比
- **色彩**：默认浅色（暖白 #F4F4F0 + 深墨 #16161A + 深松石绿 #0B8F63），系统深色时自动切换暗房版（近黑 + 荧光青绿）
- **字体**：等宽字体承载一切数据（体积 / 帧数 / 帧率 / 时间码），标题用超重紧字距，编号区标题 + 宽字距仪器标签
- **签名元素**：装片区取景框四角标记、胶片孔装饰、逐帧过片进度动画（帧格逐个点亮）、结果页巨型等宽数字、✓/✗ 优缺点药丸标签
- **动效**：弹簧曲线 cubic-bezier(0.32, 0.72, 0/1) 贯穿分段拨杆、卡片上浮、选项回弹；按钮 hover 扫光；复制成功变形；遵守系统「减少动态」偏好
- 图标为全套内联 SVG 线性图标，无任何外部依赖

## 实现要点

- **延迟归一化**：修复导出器写出的 0ms / 超大延迟（<20ms 浏览器按 100ms 渲染，属于异常数据）。只改 GIF 流里的延迟字节，**不重新量化像素**，所以不会让文件变大
- **全局调色板**：ffmpeg 路径用整段视频统计调色板（`stats_mode=full`），Pillow 路径从多帧采样合成色板，避免"后面才出现的颜色被映射成首帧最接近的颜色"（例如 Finder 蓝色文件夹变青绿）
- **体积预测 + 并行尝试**：按「像素面积 ~ scale²、色彩收益 ~ (colors/256)^0.75」建模，跳过不可能达标的档位，多档并行编码
- **引擎降级链**：ffmpeg → Pillow；ffmpeg 的 fps 过滤器在「总时长 × 目标帧率 < 0.5」时会丢弃唯一帧，已加安全下限与失败重试
- **异常 GIF 防御**：非法的 RGB 元组透明色（Pillow 编码器会崩溃）会被自动剥离后重试
- **透明保留**：ffmpeg 路径下透明区域保留；Pillow 兜底时合并白底并明确警告
- **结果变大提醒**：手动模式下输出比原图大超过 2% 会明确警告
